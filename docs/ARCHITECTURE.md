# アーキテクチャ — Sim と実機の対応関係

## ニューラルネットワーク

実機(C)と Sim(Python)で**完全に同一**の構造・定数を使います。
ズレると学習した重みが実機で正しく動きません(過去に事故あり)。

```
obs(7) → tanh(obs_n @ W1) → hidden(16) → tanh(h @ W2) → action(2)
```

バイアス項はありません(実機の `nn_forward()` を単純に保つため)。

### 観測ベクトル obs[7]

| idx | 内容 | 単位 | 正規化定数 |
|---|---|---|---|
| 0 | 傾き角(ジャイロ積分推定値) | rad | `ANGLE_SCALE = 30° in rad` |
| 1 | 角速度 | rad/s | `GSPEED_SCALE = 5.0` |
| 2 | 左車輪位置 | rad | `MPOS_SCALE = 10.0` |
| 3 | 右車輪位置 | rad | `MPOS_SCALE = 10.0` |
| 4 | 左車輪速度 | rad/s | `MSPEED_SCALE = 10.0` |
| 5 | 右車輪速度 | rad/s | `MSPEED_SCALE = 10.0` |
| 6 | 電池電圧 | V | `(V - 7.5) / 1.5` |

**この定数群が Sim と app.c でズレていないかは
`test_sim_matches_appc.py` が機械的に検証します。**

### 出力経路(実機 app.c)

```c
float act_avg = (act[0] + act[1]) * 0.5f * OUTPUT_GAIN;   /* OUTPUT_GAIN = 1.5 */
int pl = (int)(act_avg * 100.0f);                          /* 整数化 */
if (pl > 100) pl = 100;  if (pl < -100) pl = -100;         /* ±100クリップ */
/* 左右に同じ値を出す(旋回制御はしていない) */
```

左右を平均化しているため、**差動制御は実質的に無効**です。
ジャイロが前後の傾きしか測れず、旋回による横倒れがログに現れないため、
応急処置としてこうなっています。

この経路は Sim 側でも `--fidelity-output-path` で再現されます。
`|平均act| > 1/1.5 ≈ 0.667` で常に飽和する、という実機の特性が入ります。

## 物理忠実化フラグ(Phase 2 で導入)

Sim を実機に近づける8項目。各々独立に ON/OFF でき、`--fidelity-all` で
一括有効化します。**1つずつ入れて効果を測る**設計です
(一度に全部入れると何が効いたか分からなくなるため)。

| フラグ | 内容 | 実機での根拠 |
|---|---|---|
| `--fidelity-motor-speed` | モータ最高速度を 115 → **17.8 rad/s** | EV3ラージモータ無負荷 約170rpm。旧値は6.5倍過大だった |
| `--fidelity-gyro-est` | obs[0] を真値ではなく**ジャイロ積分推定**に | 実機は角速度しか測れず、ゼロ点が鉛直とは限らない |
| `--fidelity-output-path` | 左右平均化 + OUTPUT_GAIN + 整数PWM + ±100クリップ | 上記 app.c の出力経路と同一 |
| `--fidelity-ctrl-rate` | 制御周期 10ms → **5ms** | `WAIT_TIME_MS 5` |
| `--fidelity-fall-angle` | 転倒閾値 30° → **45°** | `FALL_ANGLE_DEG 45.0f` |
| `--fidelity-quantization` | エンコーダ1度量子化 + モータ不感帯8% | センサ・モータの実特性 |
| `--fidelity-startup-deadtime` | 起動時0.15秒の無制御落下 | 尻尾解放〜制御ループ開始までのログファイル生成時間 |
| `--fidelity-battery-sag` | 負荷に応じた電圧降下 | app.c は毎ループ実測している |

### 効果の実測(v7の重みで累積投入、100シード)

| 段階 | 平均生存 | 中央値 |
|---|---|---|
| 全OFF(忠実化前) | 24.25s | 29.99s |
| +モータ速度 | 13.83s | 1.83s |
| +ジャイロ推定器 | 11.95s | 1.77s |
| +出力経路 | 19.82s | 29.99s |
| +制御周期/転倒角/量子化 | 17.17s | 30.00s |
| +起動デッドタイム | 10.59s | **0.56s** |
| +電池サグ(= 全ON) | 10.29s | **0.55s** |

**3大要因は モータ速度飽和・ジャイロ推定器・起動デッドタイム**でした。

> ⚠️ `startup_deadtime_s`、`motor_deadband`、`battery_sag_v_per_unit_pwm`、
> `max_speed_realistic` はいずれも **engineering estimate(未実測)** です。
> 実測較正すると更に精度が上がる余地があります。

## ドメインランダム化

通常条件では毎エピソード以下をランダム化します。`difficulty`(0〜1)で
幅を絞れ、カリキュラム学習に使います。

| パラメータ | 範囲(difficulty=1.0) |
|---|---|
| 初期傾き | ±3° |
| 重心オフセット X/Y/Z | ±8mm / ±6mm / ±15mm |
| 本体質量 | 0.8〜1.2倍 |
| 慣性 | 0.7〜1.3倍 |
| 摩擦 | 0.5〜1.4倍 |
| 電池電圧 | 6.0〜8.4V |
| トルク損失率 | 0.3〜0.7 |
| 最大トルク | 0.8〜1.2倍 |
| 最大速度 | 0.85〜1.15倍 |
| ジャイロノイズ | 0.5〜2.0倍(基準0.5dps) |
| 制御遅延 | 0〜20ms相当 |

### オプション機能

- **`--weight-ball`**: body_link とは別の小さな剛体(10〜35g)を fixed joint で
  ランダムな位置に取り付ける。単一リンクの対角慣性テンソルを原点シフトする
  だけでは再現できない**真の非対角慣性結合**を導入する。v13以降で有望だった
- **`--max-push-force N`**: 「人が手で押す」外乱。エピソード中ランダムな
  タイミング(0.5〜2.0秒)・向きで水平方向の力を0.1秒間加える。v16で使用

**`WORST_CASE_SEED = 9999`** を引いたときだけ、全パラメータが最も厳しい側に
固定された「複合最悪条件」になります(difficulty の影響を受けない)。

## 報酬設計

```python
r  = 1.0                                     # 生存ボーナス
r -= 20.0 * pitch**2                         # 傾きペナルティ
r -= 0.01 * (pl**2 + pr**2)                  # 出力ペナルティ
r -= 1.0  * (norm_spd_l**2 + norm_spd_r**2)  # 速度ペナルティ(★正規化済み)
r -= 0.05 * (obs[2]**2 + obs[3]**2)          # 位置ペナルティ
r -= 2.0  * (pl - pr)**2                     # 左右差ペナルティ
r -= 0.01 * (obs[2] - obs[3])**2             # 位置左右差ペナルティ
# 位置バリア(POS_LIMIT_RAD の60%超から4乗で急増)
# 転倒 or 位置超過で -100
```

**速度ペナルティは `max_speed` に対する正規化値の二乗**です。
生の rad/s を使うと `max_speed` を変えた瞬間に校正が壊れます
(実際に壊して19世代停滞した。`docs/LESSONS.md` 参照)。

`--legacy-reward` で v7 時代の報酬設計に戻せます。

## 評価

```bash
python3 benchmark_100seed.py --seeds 100 --fidelity-all --w1 ... --w2 ...
```

- 固定seedレンジで評価し、**必ず同一スクリプト実行内で複数バージョンを比較**する
  (コードを変えると同じseedでも引かれる乱数列が変わるため、異なる実行間の
  絶対値比較は無意味)
- 成功判定は `done` フラグではなく**転倒角度・位置超過を obs から直接判定**する
  (`EV3WayEnv.step()` は時間切れでも `done=True` を返すため)

### 見るべき指標

| 指標 | 用途 |
|---|---|
| 平均/中央値 生存時間 | Sim上の基本性能 |
| 30秒完走率 | 同上 |
| **PWM飽和率** | **実機性能の予測指標**(低いほど実機で良い) |

## 学習の流れ(CMA-ES)

```
v7(実機最高記録)
  └→ Phase 4 Stage1: 忠実化Sim + オモリ玉、難易度上限0.5
       └→ Stage2 (= v15): 難易度上限1.0  → 実機では v7 に負けた
            └→ Stage3 (= v16): + 押し外乱 3.0N  → 実機未テスト
```

各段階は前段から warm start します。**難易度は一気に上げず段階的に**
(difficulty=1.0 では個体の65%が1秒未満で転倒し、CMA-ESが個体差を評価できる
「勾配」がほぼ消えるため)。
