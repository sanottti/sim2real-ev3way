## 結論: v7を上回れず。ただし前回より明確に改善

早期終了条件をstreak方式(フル難易度下で連続5世代満点維持)に堅牢化した後、
2026-09-25の`ev3way_v12_w1/w2.npy`(gen39時点)から再開して学習継続。

## 結果

- 250世代フル完走(所要222.8分、自動リスタート4回、早期終了なし)
- 最終評価(狭いeval): 通常条件3本とも30秒完走(前回は2/3)、複合最悪条件0.8秒
  (前回は0.5秒)
- **100ランダムシード統計比較(v7との同一実行内比較、seed 70000〜70099)**:
  v7=30秒完走95/100・5秒未満失敗5/100 に対し、
  **v12_retry=30秒完走73/100・5秒未満失敗26/100**

## 前回(gen39早期終了版)との比較

| | 前回(gen39早期終了) | 今回(250世代フル完走) |
|---|---|---|
| 通常条件(狭いeval) | 2/3 | 3/3 |
| 複合最悪条件(狭いeval) | 0.5秒 | 0.8秒 |
| 100シード30秒完走 | 52/100 | **73/100** |
| 100シード5秒未満失敗 | 44/100 | **26/100** |

streak方式による早期終了の堅牢化は明確に効果があった(52→73)。ただし
v7(95/100)にはまだ届いていない。

## わかったこと

- 早期終了ロジックの厳格化(1世代の偶然のヒット→連続5世代の持続的な
  高性能要求)は、実際に汎化性能を大きく改善した。これは「早期終了が
  早すぎるとその時点の一時的な当たりで学習が止まり、真に頑健な解に
  到達する前に終わってしまう」という仮説を裏付ける結果
- ただし同じ根本原因(カリキュラムと既存ロジックの相互作用)を持つ
  stagnation-restartのlast_improve_gen判定はまだ未修正のまま残っており、
  gen1・gen51・gen101・gen151で不要なリスタートが発火し続けていた
  (実害は限定的だが、探索の効率は損なわれていた可能性がある)
- 250世代フルに使い切ってもなおv7(2026-09-23、200世代)に届かないことから、
  単純な世代数の問題ではなく、A(複合最悪条件の重み付け)・D(位置バリア)・
  F(ステップ正規化)・G(評価シード増量)を組み合わせた新しい報酬設計自体が、
  この問題設定において必ずしもv7の報酬設計より優れているとは言えない
  可能性が高まった

## 次にやること

- stagnation-restartのlast_improve_gen判定もcurriculum_doneを考慮するよう
  修正すれば、さらに改善する余地があるかもしれない
- あるいは、報酬設計の見直し(A+B+D+F+G)自体をこれ以上追求せず、v7の
  報酬設計をベースラインとして維持し、他のアプローチ(提案#5等)に注力する
  方が効率的である可能性
