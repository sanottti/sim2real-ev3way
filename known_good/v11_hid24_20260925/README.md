# v11 — 隠れ層16→24拡大 — v7に劣るという結論(2026-09-25)

> **【2026-09-29 訂正】この比較結果は無効。** `ev3way_train_run.py`の
> `N_HID`(このバージョン以降24)とapp.c実機のv7(16)が不一致であるだけでなく、
> `train_v11_migrate.py`はMPOS_SCALE=10.0で移行の数学的等価性を検証していたが、
> 実際の学習・100シード評価はモジュールのデフォルト値MPOS_SCALE=3.0で
> 走っていたと判明した(学習3.0/検証10.0のミスマッチ)。**v11の23/100という
> 惨敗は、拡張自体の失敗ではなくこのミスマッチで説明がつく可能性が高い**。
> Phase 1(N_HID/MPOS_SCALEをapp.cに合わせて復元)完了後に再評価が必要。

## 結論: v7を上回れず。app.cはv7のまま維持

v7の重みを隠れ層16→24に拡張してwarm start(新規8ユニット分はW1側を小さい
ランダム値・W2側を0で初期化し、gen0時点で誤差0.0のv7同一挙動から開始する
よう検証済み、`train_v11_migrate.py`)。popsize=200, generations=250,
stagnation-limit=50で学習。

## 結果

- 250世代完走(所要946.3分=15.8時間、途中killなし)
- gen23でbest_reward=1102.7に到達後、**一度も改善しなかった**
- 停滞検知による自動リスタートが**4回**発火(gen73, gen123, gen173, gen223)
  したが、いずれもgen23の解を一度も上回れなかった
- 最終評価(狭いeval): 通常条件3本中1本のみ30秒完走(他は0.5〜0.9秒)、
  複合最悪条件0.3秒
- **100ランダムシード統計比較(v7との同一実行内比較)**: v7=30秒完走52/100・
  5秒未満失敗48/100 に対し、**v11=30秒完走23/100・5秒未満失敗77/100**。
  v11はv7より明確に劣る

★注記: この52/100という数値は、以前(2026-09-24)に確立した「v7=94/100」
という基準値とは異なる。理由は、A/B/D/F/G実装の一環でEV3WayEnv.reset()の
乱数消費ロジックを内部的に変更した(カリキュラム対応の`scaled_uniform()`
ヘルパー導入)ため、difficulty=1.0であっても統計的に同一分布ながら、同じ
seed整数から具体的に引かれる乱数値の並びが変わった。したがって異なる
コードバージョン間でのseed値ベースの絶対値比較はできない。ただし今回の
v7 vs v11比較は**同一スクリプト実行内・同一seed列**で行っているため、
両者の相対的な優劣は堅牢な結論である。

## わかったこと

隠れ層拡大(16→24)は、少なくとも今回の設定(v7からのwarm start、旧報酬設計、
250世代・4回リスタート)では改善につながらなかった。gen23の解が極めて
安定した局所最適(または収束領域)になっており、4回の独立したsigma0=0.3
リスタートでも一度も脱出できなかった。これは表現力を増やすだけでは
CMA-ESの探索能力そのものの限界(v9・v10でも繰り返し確認された局所最適への
はまりやすさ)を解決しないことを示唆する。
