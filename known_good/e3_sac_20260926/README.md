# E3(SAC) — warm start地点から一歩も改善せず(2026-09-26)

## 結論: PPO(v10)と全く同じパターンで、改善なし

`ev3way_train_sac.py`を新規実装。app.c互換の決定的2層tanhネットワーク
(W1/W2)をActorとし、SAC標準の状態依存log_std(別ヘッド)・twin Q-network・
エントロピー自動調整(auto alpha)を実装。PPOで踏んだ「rollout収集が
WORST_CASE_SEEDをほぼ引かない」バグの教訓を踏まえ、最初から
`--worst-case-prob`でWORST_CASE_SEEDを混ぜる設計にしていた。

v7の重みを隠れ層24に拡張してwarm start(v11-v14と同じ手法)し、
total_steps=1,000,000で学習。

## 結果

- 所要時間34.1分でtotal_steps=1,000,000完走
- **best_reward = 1090.2(warm start開始時点と完全に同一)**。学習中一度も
  改善が見つからなかった
- 保存された最終重みを数値検証したところ、W1の元の16列(v7由来部分)は
  v7の元の重みと完全一致(誤差1e-5未満)。新規追加した8列も含め、実質的に
  warm start時点から一切変化していない
- 最終評価(狭いeval、seed 9000〜9002+複合最悪条件): 通常条件1/3のみ
  30秒完走(他2本は0.6〜0.8秒)、複合最悪条件0.4秒。重みがv7の元の重みと
  完全一致しているため、これは実質的に「v7の重みをこの3+1個のseedで
  評価した結果」そのものであり、SAC固有の劣化ではない(狭いevalは
  サンプル数が少なくばらつきが大きいことの一例)

## PPO(v10)との比較

| | PPO(v10、2回試行) | SAC(E3) |
|---|---|---|
| warm start地点からの改善 | なし(2回とも) | なし |
| 保存された最終重み | warm start地点と完全一致 | warm start地点と完全一致 |
| 実装した対策 | worst_case_prob(2回目で追加) | worst_case_prob(最初から) |

**2種類の異なるpolicy gradient手法(PPO・SAC)がどちらも同じ結果(warm start
地点から一歩も改善できない)に終わったことは、CMA-ESの局所最適への
はまりやすさとは異なる、別の種類の限界を示唆している**。考えられる仮説:

- v7の重みが実際にこの問題設定における非常に強い局所最適(あるいは
  グローバルに近い最適)であり、勾配ベースの手法では改善の余地を
  見つけにくい
- 勾配ベースの手法(PPO・SAC共通)は、warm startされた既に良い決定的方策の
  近傍で探索ノイズを加えると、性能が大きく崩れる(このセッションで
  繰り返し観測された現象)。崩れた状態から回復するだけで精一杯で、
  それを超えて改善する余地に到達する前に学習が終わってしまう
- 両手法とも「決定的方策の近傍を探索的にサンプルする」という共通の
  設計(squashed Gaussian policy)を採用しており、この設計自体に
  何らかの限界がある可能性(例: 探索ノイズの初期スケールやスケジュール、
  もしくはより根本的なアーキテクチャ上の制約)
